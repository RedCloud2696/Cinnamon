## 1. 项目目标

搭建一个**个人学习笔记门户网站**，把平时整理的 OneNote / PDF 笔记按科目分类公开，方便自己和同学复习查阅。

### 功能

- 按科目 → 章节多级分类展示，侧边栏树形导航
- PDF 在线预览 + OneNote（`.one`）/ PPT（`.pptx`）原件下载
- 模糊搜索（文件名 + 科目别名）
- 独立序言页，可切换显隐
- giscus 留言区
- 响应式适配移动端

### 展示形式

- 侧边栏 + 内容区双栏布局
- 粉棕暖卷配色（核心色 `rgb(254,151,151)`）
- 索琳主题背景图 + Terraria 素材书籍图标

### 自动部署

- push 到 GitHub → Actions 自动扫描 `notes/` 重建索引 → Pages 更新
- 全程无需手动干预

## 2. 技术选型

**最终方案：纯静态 HTML + CSS + 原生 JS**

| 候选方案 | 落选原因 |
|------|------|
| Docsify / VuePress / MkDocs | 为 Markdown 文档设计，不适合管理 PDF / 二进制文件 |
| Hugo / Jekyll | 每篇笔记都要写前言，太重 |
| **纯静态** | 零依赖、完全可控、从文件夹结构自动生成索引 |

### 关键技术点

- **索引生成**：Node.js 脚本 `scripts/build-index.js` 递归扫描 `notes/`
- **前端渲染**：原生 JS 操作 DOM，无框架
- **留言系统**：giscus（基于 GitHub Discussions，按 pathname 映射）
- **浏览统计**：不蒜子 UV 计数
- **部署**：GitHub Pages（Deploy from branch：`main` / `/ (root)`）+ Actions 自动更新索引

## 4. 部署方式

### GitHub Pages 设置

- **Source**：Deploy from a branch
- **Branch**：`main`，目录 `/ (root)`
- 仓库根目录必须有 `.nojekyll`

### GitHub Actions 工作流（`deploy.yml`）

- 触发：push 到 `main` / `master`（忽略 `notes-index.json` 自身的改动，避免循环），或手动 `workflow_dispatch`
- 流程：检出 → 安装 Node.js 20 → `node scripts/build-index.js` → 若索引有变化则提交推送
- **需要仓库 Settings → Actions → General → Workflow permissions 设为 “Read and write permissions”**，否则机器人无法推送更新后的索引

> 注意：这个工作流只负责重建索引，**不负责部署 Pages**。Pages 走的是分支部署。

### 索引生成规则

- 同名 PDF + `.one` → 配对为一份笔记（预览 + 下载）
- 同名 PDF + `.pptx` → 配对（预览 + 课件下载）
- 仅 `.one` → 主笔记；同目录下未配对的 PDF 自动挂为其子笔记
- 支持 `index.json` 自定义排序（`order` 数组）
- 支持 `flat: true` 平级排列（跳过自动挂载）
- 支持自定义图标（`icon` 字段）

## 5. 日常操作流程

### 更新笔记

1. 把 `.pdf` + `.one` 放进 `notes/科目/`（同名自动配对）
2. 需要排序就在该目录的 `index.json` 写 `{ "order": ["..."] }`
3. 需要搜索别名就改 `subjects.json`
4. 本地预览（可选）：`npx serve D:/Cinnamon`
5. 推送：

   ```bash
   git -C D:/Cinnamon add -A
   git -C D:/Cinnamon commit -m "描述"
   git -C D:/Cinnamon pull --rebase
   git -C D:/Cinnamon push
   ```

6. 等 1–3 分钟，网站自动更新

### 更新序言

改 `index.html` 和 `app.js` 中**对应的两份 HTML**（`app.js` 的 `WELCOME_HTML` 里有一份副本，两边必须同步修改）。

### 提交信息规范

commit message 控制在 **5 个字以内**，例如「加普化实验」「改排版」「修死链」。

## 7. 体积与限制

- `notes/` 约 279 MB：`.one` 9 个约 175 MB、`.pdf` 39 个约 63 MB、`.pptx` 9 个约 41 MB
- `.one` 是二进制格式，**每次修改都会在 git 历史里再存一整份**，仓库体积增长很快
- GitHub 单文件硬限制 **100 MB**，目前最大的 `notes/普通化学实验（乙）/讲义/汇总.one` 约 83 MB，已接近上限
- **不要启用 Git LFS**：Pages 无法读取 LFS 指针文件，`.one` 下载按钮会失效

## 附录 A：排序机制

1. 每个目录独立读取本目录的 `index.json`，提取 `order` 数组
2. `order` 中的项目按指定顺序排在前面，未列出的项目按拼音排在后面
3. **每个目录只排自己的直系子项，不递归排子目录的内容**
4. 文件夹和笔记统一排序，不再区分先后

### 历史上踩过的坑（2026-07-06 复盘）

**症状**：平级笔记被排到所有文件夹后面；子文件夹内的 `index.json` 排序被打乱。

**原因**：

1. 旧逻辑先排 `folders` 再排 `notes`，然后 `return [...folders, ...notes]`——文件夹永远在前
2. 父级目录的 `sortByOrder(n.children)` 会递归套用父级 `orderList`，覆盖子文件夹自己的排序

**修复**：

1. 合并文件夹和笔记为统一数组 `allItems` 一起排序
2. 删除递归排序——每个目录只对自己的直系子项负责

## 附录 B：常见问题

### push 被拒绝？

远程有 Action 自动提交的新索引。先 `git pull --rebase` 再 `git push`。

### `notes-index.json` 冲突？

运行 `node scripts/build-index.js` 重新生成，`git add notes-index.json`，再 `git rebase --continue`。

### 侧边栏没加载？

检查 `app.js` 是否有语法错误：`node -c app.js`。

### 改了笔记但网页没变？

1. 确认已 push，且 Actions 运行成功
2. 浏览器强制刷新（索引请求带了 `?v=` 时间戳，一般不会缓存）
3. 检查该目录的 `index.json` 是否把文件排除在外

### 本地预览？

```bash
npx serve D:/Cinnamon
# 或
python -m http.server 8080 -d D:/Cinnamon
```
