## 1. 项目目标

搭建一个**个人学习笔记门户网站**，核心需求：

### 功能
- 按科目→章节多级分类展示笔记，侧边栏树形导航
- PDF 在线预览 + OneNote(.one) 文件下载
- 模糊搜索（文件名 + 科目别名）
- 独立序言/欢迎页，可切换显隐
- 更新通知栏
- 学期回顾系统（JSON驱动、绩点隐藏、三区块评价）
- giscus 留言区
- 响应式适配移动端

### 展示形式
- 侧边栏 + 内容区双栏布局
- 粉棕暖卷配色方案（核心色 `rgb(254,151,151)`）
- 索琳主题背景图
- Terraria 素材书籍图标

### 自动部署
- push 到 GitHub → Actions 自动扫描 notes/ 生成索引 → Pages 自动部署
- 全程无需手动干预

## 2. 技术选型

### 最终方案：纯静态 HTML + CSS + 原生 JS

| 候选方案 | 落选原因 |
|------|------|
| Docsify / VuePress / MkDocs | 为 Markdown 文档设计，不适合管理 PDF/二进制文件 |
| Hugo / Jekyll | 需每篇笔记写前言，太重 |
| **纯静态** | 零依赖、完全可控、从文件夹结构自动生成索引 |

### 关键技术点
- **索引生成**：Node.js 脚本 `scripts/build-index.js` 递归扫描 `notes/`
- **前端渲染**：原生 JS 操作 DOM，无框架
- **留言系统**：giscus（基于 GitHub Discussions）
- **浏览统计**：不蒜子 UV 计数
- **部署**：GitHub Pages（Deploy from branch, main / root）+ GitHub Actions 自动更新索引

## 4. 部署方式

### GitHub Pages 设置
- **Source**：Deploy from a branch
- **Branch**：`main`，目录 `/ (root)`
- **注意**：必须有 `.nojekyll` 文件

### GitHub Actions 工作流
- 触发条件：push 到 main 分支（除 notes-index.json 外）
- 流程：
  1. 检出代码
  2. 安装 Node.js 20
  3. 执行 `node scripts/build-index.js` 扫描 notes/
  4. 将更新后的 notes-index.json 提交并推送
  5. Pages 自动从分支部署

### 索引生成规则
- 同名 PDF + .one → 配对为一份笔记
- 文件夹内唯一 .one → 自动将未配对的 PDF 挂为附属
- `.pptx` → 与同名 PDF 配对，提供下载
- `.md` → 独立笔记（Markdown 渲染）
- 支持 `index.json` 自定义排序（`order` 字段）
- 支持 `flat: true` 平级排列
- 支持自定义图标（`icon` 字段）

## 5. 操作流程

### 日常笔记更新
1. 在 `notes/科目/` 下放入 `.pdf` + `.one` 文件（同名自动配对）
2. 要排序加 `index.json`，写 `{ "order": ["..."] }`
3. 要搜索别名改 `subjects.json`
4. 本地预览（可选）：`npx serve D:/Cinnamon` 或 `python -m http.server 8080 -d D:/Cinnamon`
5. 推送：
   ```bash
   git -C D:/Cinnamon add -A
   git -C D:/Cinnamon commit -m "描述"
   git -C D:/Cinnamon pull --rebase
   git -C D:/Cinnamon push
   ```
6. 等待 1-3 分钟，网站自动更新

### 学期回顾更新
1. 编辑 `review/` 下的 JSON 文件或草稿 TXT
2. TXT 写完发我转 JSON
3. 推送同上

### 序言/通知更新
- 改 `index.html` 和 `app.js` 中对应的 HTML

## 附录A：排序机制与常见 Bug

### `index.json` 的 `order` 字段如何工作
1. 每个目录独立读取本目录的 `index.json`，提取 `order` 数组
2. `order` 中的项目按指定顺序排在前面，未列出的项目按拼音排在后面
3. **每个目录只排自己的直系子项，不递归排子目录的内容**
4. 文件夹和笔记（PDF/.one 等平级文件）统一排序，不再区分先后

### 2026-07-06 排序 Bug 复盘
**症状**：`期末题型与个人期末回忆` 作为平级笔记被排到所有文件夹后面，子文件夹内的 `index.json` 排序也被打乱

**原因**：
1. `build-index.js` 原来的逻辑先排 `folders` 再排 `notes`，然后 `return [...folders, ...notes]`——文件夹永远排在笔记前面
2. 父级目录的 `sortByOrder(n.children)` 会递归地用父级 `orderList` 重排子文件夹内容，覆盖了子文件夹自己的排序

**修复**：
1. 合并文件夹和笔记为统一数组 `allItems`，一起排序
2. 删除递归排序逻辑——每个目录只对自己的直系子项负责

## 附录B：常见问题

### push 被拒绝？
远程有 Action 自动提交的新索引。先 `git pull --rebase` 再 `git push`。

### notes-index.json 冲突？
运行 `node scripts/build-index.js` 生成新索引，`git add notes-index.json`，`git rebase --continue`。

### 侧边栏没加载？
检查 `app.js` 是否有语法错误：`node -c D:/Cinnamon/app.js`。

### 本地预览？
```bash
npx serve D:/Cinnamon
# 或
python -m http.server 8080 -d D:/Cinnamon
```
